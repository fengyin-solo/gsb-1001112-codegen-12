# 市政道路桥梁养护管理平台

覆盖道路巡查、桥隧定检、路面病害、交安设施、绿化管养、除雪防汛及养护工程管理的市政道桥全要素养护后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 风雪事件指挥板（storm）

把一次风雪过程编排成连续事件窗口，并在调度会话落结论时把同一事件号写进三处台账：

- **连续窗口**：气象时段必须首尾相接、恰好铺满气象开始～结束，不允许间隙或重叠；
  系统按「气象时段 × 作业路段」生成窗口，车辆位置上报挂接到窗口时间线。
- **封控段直调资源**：只有`封控`状态的路段可从指挥板直接调用材料与班组，限速/通行段不行。
- **三处同引一事件**：每次派发在同一事务里写入 ① 除雪作业台账（winter）② 路段阶段
  ③ 物资清单（材料扣减），共用同一`事件ID`与`派发编号`，并冻结当时天气基准。
- **状态机**：待启动 → 执行中 → 收尾 → 已关闭，只能顺序推进一格，不能跳步、回退或重开；
  关闭即冻结台账与天气基准，同时释放占用车辆归库。
- **防汛冲突**：除雪与防汛在同一路段同时占用时，必须填写应急指挥令确定优先级后才能派发。
- **事务相符**：任务派发前先校验车辆在库/未被占用、材料库存充足；任一不满足整单拒绝，
  不会出现派了车却没扣料等半成品状态。
- **断网续传**：写操作在前端先分配操作号（`stores/storm.ts`，localStorage 排队）；
  断网时本地排队，复位后调 `POST /api/storm/sync` 按操作号幂等续传，重复操作号回放首次结果，
  不二次扣减材料、不重复占用车辆。
